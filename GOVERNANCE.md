# Governance

OpenPath starts as a maintainer-led community project. @kirkwarren owns the repository and deployment account, triages work, and is the initial code owner. No educator or independent security reviewer has yet been appointed. Recruiting those reviewers is an explicit launch priority.

Anyone may propose an issue, discussion, lesson, translation, or PR. Decisions and their reasons should be recorded publicly unless they concern security or personal information. A maintainer does not have to accept a contribution simply because it passes automation.

Code and curriculum use MIT. Changing the license, collecting student data, introducing AI tutoring, or changing access/deployment architecture requires a public proposal and explicit maintainer decision. Keep the public alpha independent from Alpha School branding and proprietary curriculum.

Maintainer access is earned through sustained reviewed contributions and reliability; stars, donations, and agent throughput do not grant trust. New maintainers need explicit appointment, minimum required access, and agreement to review/security policies. Initial code-owner rules require @kirkwarren; update them deliberately when another trusted maintainer joins. The owner cannot approve their own PR, so owner-authored changes need another qualified code owner before merging under these rules.

Reviews are asynchronous. Record educational review evidence in PRs. Document contributor credit in Git history and release notes. Human-led releases publish reviewed main only; no autonomous agent merges or releases.
